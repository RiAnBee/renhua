# 禁改清单

## 一、已证伪：这些方向**不要动**

每条都给了人类侧实测值。**人类在这些方面用得不比 AI 少，有的还更多。**
把它们当 AI 特征去改，是这份 skill 最大的失效来源。

| 流行建议 | 实测 | 人类侧 |
|---|---|---|
| 把句子改短 | AI 平均句长 **δ=−0.44（新闻）/ −0.79（博客）**，两语域 p<0.01 | 人类句子更长 |
| 强制句子长短变化 | ⚠️ **本条已修订**：句长 CV 实测 **δ=−0.46/−0.62**（AI 方差小）—— 差异真实存在，但**改法是「合并碎句」，不是「制造参差」**，见 SKILL.md A3 |
| 删句内排比 | 同字开头两项 **0.61×**、三项 0.95× | 人类更多 |
| 删问句/设问 | 正文问句 **0.05×**；自建语料 δ=−0.33/−0.25（两语域稳健） | 人类是 AI 的 **17 倍** |
| 删比喻 | 比喻标记 **0.42×**；自建语料口语 δ=−0.35（AI 少用） | 人类 **2.4 倍**（独立成段 **8 倍**） |
| 改被动句 | 中文无差异；英文无施事被动 AI 是人类 **一半** | 人类更多 |
| 改动词名词化 | 中文实测 **0.52×**（人类更多） | 人类更多 |
| 加第一人称 | 无来源支持；（姿态实验显示加第一人称需换姿态，但那不解决 AI 味） | — |
| 删破折号 | ⚠️ **本条已修订**：中文侧两源同向 —— 自建语料正式语域 2.35×、参考基线 3.0×，**AI 用得多**。英文侧相反。**本项目面向中文 → 可作为正式语域的可选规则**，但幅度小（δ=+0.21），不作常开 |
| 删弯引号 | 中文正文本就用「」"" | — |
| 调高温度去味 | 温度 0.3→1.5 只把单簇率 62%→38% | — |
| 换模型换味道 | 跨模型相似度 **71–82%** | — |
| 用 persona/人设 | 单独用降不到 0.7 以下；自建姿态实验证实换姿态**不改变**起手式 | — |
| 补虚词、补口语 | 人类确实更多（"就/很/了" 0.45×），但"补"无法验收 | — |
| 多轮递归改写 | JSD 达 **0.476**，人类编辑是 **0.20–0.30** | — |
| 增加感官细节 | AI 用身体感官写情绪 **81%** vs 人类 **38%** —— **方向相反** | 人类更少 |
| "show 不要 tell" | AI 用明确情绪标签 **8%** vs 人类 **29%** —— AI 已经在 show | 人类更多标签 |
| 提高词汇多样性(TTR) | 越新模型 TTR **越高**（AI 42.99 vs 人类 38.49） | 人类更低 |

## 二、人类侧有地板、但**不能自动改**

这些确实 AI 更多，但触发条件苛刻，需要反例门：

| 项 | AI vs 人类 | 为什么不能自动改 |
|---|---|---|
| 破折号 | 3.0×（中文基线） | 与英文研究方向冲突 |
| 拟人喻体 | 0.018 vs 0.002 /千字（7.3×） | 绝对频率太低，命中一次很可能是偶然 |
| 序数词小标题 | 3.1× | 公文一级标题合规（一、二、三） |
| 顿号罗列过密 | 1.8× | 材料本身必须完整列出时（法规、配置项） |
| 句首连接词 | 0.18 vs 0.03 /千字 | 无中文对照；人类侧本来就常用 |
| 前置过长定语 | 单侧 0.42/千字 | 学术文献对中文**零证据** |
| 「当……时」 | 单侧 0.26/千字 | 零证据；删了改变时间关系 |
| 「对于……来说」 | 单侧 0.22/千字 | 零证据；删了**改变命题范围** |
| 「这意味着」 | 单侧 0.15/千字 | 零证据；常承载推理 |

## 三、整族停用：语域豁免

**语域清单见 `SKILL.md` 闸门 1 —— 那是全项目唯一定义。本节不重复列举，避免两处不一致。**

要点：

- 命中规范格式的语域 → **整族停用 A3–A5 与 B1–B5**，只保留 A1、A2 和 T0 清理
- **混合文档按段判**：README、技术博客、产品文档是**容器**不是体裁 ——
  里面的表格/参数/字段/代码块停用，散文段正常处理

**理由**：这些文体本身就要求格式统一、措辞一致、标点规范。
在这里"去 AI 味"等于破坏体裁规范。

维基百科的 AI 特征清单（由大量编辑从真实 diff 归纳）写着：

> this list is *descriptive*, not *prescriptive*
> The patterns listed here are also only potential *signs* of a problem, not *the problem itself*.
> Please do not merely treat these signs as the problems to be fixed; **that could just make detection harder.**

同页明确列为"无效指标"（不能作为判断依据）的还包括：
完美语法、口语与正式语域混用、"平淡/机器人腔"、花哨学术文风的整体印象、
孤立的转折词、无来源内容、古怪的 wikitext、书信体格式。

### 关于排版层（Markdown 加粗/标题形态/列表密度）

**本 skill 不处理排版层** —— 因为**没有人类侧对照证据**，不能凭观感立规则。

具体地：

| 项 | 为什么不管 |
|---|---|
| `**加粗**` 密度 | 无人类侧基线；且「去加粗」属改格式，不在 {删,合并,移,还原} 内 |
| 小标题的**层级与顺序** | 属结构，禁改清单保护 |
| 小标题的**措辞同构** | ✅ **管** —— 归 A3（属"移"，见 SKILL.md A3 小节） |
| 破折号密度 | 中英方向冲突，默认不启用（见下） |
| 列表项数与嵌套 | 属结构 |

**执行者注意**：用户说"读着像 AI"时，观感可能主要来自排版层。遇到这种情况，
**如实告诉用户"这部分不在本 skill 射程内"**，不要为了满足诉求去动加粗或标题层级。

## 四、绝对不可动

| 类别 | 规则 |
|---|---|
| 专名 | 人名、机构名、产品名、地名、品牌 —— **一个字都不换** |
| 数字 | 数值、单位、日期、比例、金额、时长 —— **不换算不省略** |
| 术语 | 专业术语、固定译法、代码标识符 —— **不改** |
| 引语 | 引号内的所有内容（含他人原话） —— **不改** |
| 立场 | 作者的判断、倾向、褒贬 —— **不磨平** |
| 限定 | "可能""通常""在某些情况下""据说" —— **不删不加强** |
| 结构 | 段落数、段落顺序、章节层级、列表/表格/引用/代码块位置 —— **不动** |
| 人称 | "笔者""我""我们"或无第一人称 —— **跟原文** |
| 地域 | 简繁、地域用词（软件/軟體） —— **跟原文** |
| 粗糙 | 口语、方言、网络用语、刻意的残缺句 —— **不改** |

## 五、素材不实 ≠ AI 味

以下看着像 AI 特征，实际是**事实问题**，不是风格问题：

- 引用链接 404、ISBN 校验码错、DOI 指向不相关论文
- 引用了不存在的来源
- 具体数字与事实不符
- 页面/章节标题下没有正文

这些**不要用改写规则处理**，而是标注出来让作者核实。

同理：**翻译腔 ≠ AI 味**。人类译者的成品里近半数被判为非原生中文。
"读着像翻译"不能作为判定 AI 写作的依据。

## 六、如果用户坚持要改

用户明确要求改清单里的某条时，按用户的来 —— 但**先说明风险**，并在改动台帐里标注
"此项属已证伪方向，按用户要求执行"。

用户的要求优先于这份清单。
