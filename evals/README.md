# 中文表达编辑评测

本目录只用于维护者离线验证，不是 skill 的运行依赖。协议冻结于2026-09-22，先于本轮核心修改和改稿比较。

## 本轮输入

`cases.jsonl` 是36篇原创合成开发稿，分技术产品、科普问答、工作沟通、观点评论、新闻转述、叙事口播六类，每类6篇。场景、人物、事件和数字均为测试用虚构内容，不是现实报道或真人经历，可随项目MIT许可使用。

字段：`id`、`split`、`category`、`source_group`、`title`、`task`、`text`、`protected_meaning`、`quality_intent`、`provenance`、`author_model_alias`、`license`、`not_human_authored`。`quality_intent`与`protected_meaning`是生成者提出的检查线索，须对照全文审核，**不是人工金标**。评审不能把标签当答案。

另有120篇不同主题的完整合成确认稿，在修改核心前保存到本地 `.harness/reconstruction/confirmation-sealed.jsonl`。设计者在冻结前不阅读其正文；开发与确认的哈希及时间在 `split-manifest.json`。它们来自同一生成模型角色，不是120位独立作者，不能替代报告要求的跨作者、真实世界确认集。旧的新闻／博客语料及重构报告示例已参与设计，不能充当未见确认样本。

## 比较组与执行

开发稿比较四个实际编辑条件，另保留原稿：

1. 简单强提示。
2. 0.7.0 的核心＋必读反例，条件名 `old_required`；完整旧版仍在本地冻结。直接提示不提供可选文件工具访问，因此不代表旧版所有路由能力。
3. `lieflat-less-ai-tone` 的冻结公开主体。
4. 新 renhua。
5. 原稿不改，作为是否值得编辑的参照，不发起生成调用。

同组输入、用户用途和生成设置相同；系统指令仅切换编辑条件。完整提示、skill内容哈希、模型角色、配置的模型ID、实际响应可用元数据、输出、耗时与失败写入本地运行记录。旧版重台帐保持其原合同，评表达时只看正文；不能把为公平比较而改造的旧版写成原版。

最初以 harness 的 `default` 与 `smol` 角色尝试批量执行，但长等待被中断，未落盘的调用不计成功。恢复后改用有期限、可断点续跑的OMP CLI批次，指定具体模型并从响应事件记录实际provider/model、token和停止原因；采样中未显式指定的参数不猜测。

技术失败、空输出、截断和解析失败单列，不能写成零改动。最多补做一次重试，保留初次错误与重试；报告首次成功率和最终成功率。不无限重跑直到出现喜欢的结果。

恢复后的本地驱动为 `.harness/reconstruction/run_comparison.py`：每次选下一批未尝试项目，逐请求落盘，单请求有截止期限。旧成功项不重跑，失败重试另存，不使用一条无限等待覆盖整批任务。可用模型与阻塞模型分开列出；服务超时不算某个skill表现差。该驱动只服务这次离线调查，不加入skill依赖。

本轮CLI首试的45秒截止造成部分流式输出被截断，不能按完整改稿评价。仅对失败项补做一次90秒截止的重试，并记录两次状态；这不是同一时延预算下的无偏性能比较。初次可用率与补救后的可用率分别报告，不据此评定哪套提示更优。

开发复核后有一次通用边界修正：不加强近义判断、不把转述升级为原话、默认不拆合段落。初稿条件 `candidate` 保留，修订版单独记为 `candidate_r2`，重新覆盖36篇开发稿，使用90秒截止；基线复用原先完成的输出，不重复计费。审阅页配对最终修订版与简单提示，不能把两版输出混成一个胜率。它不是同时重跑全部条件的确认试验。

确认阶段原计划使用冻结候选，与简单提示在120篇合成确认稿上配对；本轮该阶段尚未执行，确认集保持封存，等待开发审阅与独立模型条件。确认结果一旦被用来调规则，就不能继续称为独立验证。未参与开发的第三模型、真实作者稿与真人盲评需单独组织，不用同模型合成数据冒充。

## 先查保真，再看是否值得采用

**保真**：对照全文检查事实、数字实体、条件、例外、否定、来源、因果、责任、请求力度、引语、规范结构与作者语气。数值、代码与链接比对可辅助，但不能证明语义完全不变。每个失败要给原文、改稿和实际损失。

**采用偏好**：在给定用途与受众下，一对全文随机显示为A/B，选A更好、B更好、基本相当或无法判断。问“更愿意采用哪版、为什么”，不问“哪版像AI”。不向评审提供方案名、原稿来源或预期质量标签。需要查含义时提供原稿。

模型辅助评审用同一明确问题和成对换序，保留分歧；不能自动把同模型喜好当真人偏好。真人确认需两名中文读者独立判断，关键分歧另请复核。专业文本由相关使用者确认。

严重保真失败单列，并使该次候选比较失败，不能被其他文档的漂亮改写抵消。双方都失败记双方失败，不能装成正常平局。全量失败率与成功输出上的偏好同时报告，避免只选成功稿。

## 预先约定的采用口径

- 主比较是新候选对简单强提示；对原稿、旧版和上游的比较解释必要性与得失。
- 净偏好 =（胜−负）/有效配对文档数，平局留在分母；无法判断与技术失败分别报告。
- 独立单位为完整文档／同源主题簇，不是运行次数。重复生成只估计稳定性。
- 提议的确认门槛为净偏好至少+10个百分点，95%区间下界高于0；这是产品选择，不是文献定律。
- 还需满足预设保真风险要求；少量样本零错误不等于安全率已证明。120篇独立样本零严重错误的95%单侧近似上界仍约2.5%，合成同源数据更不能给真实世界安全保证。
- 分类别报告退化、声音被磨平和不必要修改；不显著不等于等价。
- 若候选无法胜过简单提示，优先更简单的核心。不因为项目已有规则多而保留它们。

## 如何复核

本地 `.harness/reconstruction/` 保存基线、完整输入、请求与输出、错误、冻结哈希和审阅页，不提交私人数据、上游副本或临时模型结果。公开状态与执行证据见 [升级执行记录](../docs/plans/2026-09-22-renhua-reconstruction.report.md)。记录中必须分别说明：静态一致性、直接提示、真实skill加载、模型辅助评审、真人盲评。

贡献者可按同一协议运行自己的模型。无需检测器、嵌入阈值、运行时脚本或评测平台。更换提示措辞或案例也可能改变行为，需要重跑相关边界。
