# Prompt 是情境的有损压缩：替代解释审查

日期：2026-10-25

## 结论先行

现有数据最能区分的是三件事：模型文本的收缩并不只是“更高概率的词串”（A 作为总解释不成立）；AI 并不稳定地落在某个体裁的人类密度中心/代表文本附近（D 的强版本与数据不符）；而在项目文档这种必须引用版本、命令和路径的厚情境中，AI 的具体指涉回到人类区间（支持 E 的方向）。

其余解释不能由现有自然语料对照单独裁决：没有跨模型、解码控制、英译中平行语料、礼貌/情绪标注，也没有随机化操纵“情境厚度”。因此，下面的“支持”是对预测的支持，不等于因果识别。

## 数据、命令和判定规则

主语料是五种中文体裁的人类文本（60 篇）和三批 GPT-6.1 Sol 输出（v1=60，v2=57，v3=60）；另有项目文档域（人类 README 7、大厂 README 16、落地页 6）。特征是 `human_model.py` 中的 21 个形式特征，统一分析窗口为 250 个汉字；稳健性、6-gram 和指涉结果来自 `robustness.py`，文档域复制来自 `replication_docs.py`。

可复现命令（在仓库根目录执行）：

```sh
.harness/research-20261020/mechanism/.venv/bin/python \
  docs/research/2026-10-20-human-expression/mechanism/analysis/human_model.py
.harness/research-20261020/mechanism/.venv/bin/python \
  docs/research/2026-10-20-human-expression/mechanism/analysis/robustness.py
.harness/research-20261020/mechanism/.venv/bin/python \
  docs/research/2026-10-20-human-expression/mechanism/analysis/replication_docs.py
.harness/research-20261020/mechanism/.venv/bin/python \
  docs/research/2026-10-20-human-expression/mechanism/analysis/review_alternatives.py
```

最后一个脚本是本审查新增的诊断；它只调用已有 `load`、`feats` 和 `zmatrix`，不下载数据、不生成新语料。其输出固定了 A、C、D 的数字。

## 这些结果能、不能说明什么

能说明的是：一个单纯“模型偏爱高概率措辞”的解释无法覆盖 v1/v2 与 v3 的差异；“原型复制”也不能解释 AI 为什么离人类 medoid 反而比 centroid 更远。最稳定的可重复关联是**情境材料的供给**：五体裁薄情境输出的具体指涉大幅减少，而项目文档这种材料约束强的任务中，差异明显缩小。

不能说明的是：E 已被随机化地证明，或 B/C/F/G 已被排除。当前数据把体裁、提示模板、长度、模型和来源绑在一起；而且 `被`、礼貌、hedge、情绪、读者任务和责任后果都没有直接标注。故“支持 E”应读作相对于现有替代解释的解释优势，而非唯一因果结论。

## 单个最有判别力的新实验

做一个**同模型、同体裁、同主题、同篇幅、同解码参数的配对交叉实验**：每个真实任务随机分配给模型两种提示——（薄）只有体裁/主题/长度；（厚）在相同提示上加入真实材料、读者知识状态、决策后果、责任边界和明确的否定项。每个条件多次采样，并预注册 21 维几何、具体指涉、篇内 spread 和独立读者任务正确率。

判别标准是：若 E 对，厚提示应使 silhouette/η² 和体裁内收缩向人类区间移动，指涉密度随材料而变；若 A/B/C/D 是主要原因，控制情境厚度后仍应保留相同的收缩或标记偏移；若 F 是主要原因，换窗口/特征的预注册复算应消除差异。这个设计只改变情境信息量，因而比现有自然语料对照更直接地检验“prompt = lossy compression of situation”。
