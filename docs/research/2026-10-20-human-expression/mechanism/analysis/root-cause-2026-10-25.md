# AI 味根因分析：段首贴标签、段末下总括

2026-10-25。对象是本轮被用户逐条指出的失败句，以及产生这些句子的写作流程。
结论先放在这里，后面是反推、判别和证据。凡标 [推断] 的是尚未验证的环节。

## 一、结论

根因不在词，不在体裁，也不在规则条数不够，而在生成顺序：写的时候我先产出“关于这段文字的说明”，也就是这段讲什么、所以怎么样，再产出内容。这类说明句在中文里只能靠抽象主语加评价谓语成立，于是每一稿都带着同一批标记。

落到字面上，它只出现在两个固定位置：

| 位置 | 生成时先决定的事 | 产出的句子形状 |
|---|---|---|
| 段首 | 本段归到哪一类 | 标签、半句加粗、名词短语起句 |
| 段末 | 本段得出什么结论 | 总括、评价、承诺、金句 |

这两个位置都不对具体的人说话，也没有后果。评价词、无连接裸并列、“不是……而是”、报告语态，全是这个姿势的副产物。

## 二、反推：从四个失败句往回走

| # | 原句 | 上位特征 | 生成时先做的那一步 |
|---|---|---|---|
| 1 | 话讲得满，落不到具体的事上。 | 给整篇下总评，评价词替代具体毛病 | 段首先决定“这类稿子怎么归类” |
| 2 | 事实、判断、语气和作者原本的声音，一律不动。 | 并列名词直接接判断，无受话人、无后果 | 段末要“交代边界” |
| 3 | 骨架是压掉空转的主力……自我评价会自己退场。补骨架比补材料有效得多。（`SKILL.md` 第 14 行） | 拟人化收束 + 金句对比 | 段末要“给结论” |
| 4 | 0.8.0 发布后，用户审读 README 指出…… | 报告语态，把内部过程当内容 | 说明文体的默认视角是“向读者汇报我做了什么” |

四句的共同点是同一件事：句子在说明这段文字，而不在跟谁说一件具体的事。把这一层去掉，剩下的才是内容；不去掉，内容永远被包在说明里。

我上一次的“修复”正好演示了绕开检查的方式：把“话讲得满”换成“空泛、僵硬、重复，或者不合体裁”。功能没变，仍是给整篇下总评，只是换了更体面的词。用户判为补丁式改法，判得对。

## 三、五个竞争解释，哪些站不住

| 解释 | 它预测什么 | 现有证据 | 判定 |
|---|---|---|---|
| H1 词表问题 | 剔掉标记词，AI 味下降 | 修正对照组后，评价词分类 AUC 从 0.96 降到 0.69；本轮在 slop 语料上按位置统计，阳性 README 的评价词率 6.8%（段首）/12.2%（段中），大厂 README 4.6%/13.0%，几乎重合（`data-prep/runs/slop`，492 份） | 不是根因 |
| H2 体裁问题 | 只在 README 出现 | 本轮五个文件都出现：README、release 说明、CHANGELOG、案例库、`SKILL.md` | 排除 |
| H3 规则不够多 | 案例累积到一定量就收敛 | 15 条案例后仍在复发，且复发点都在段首段末；`SKILL.md` 自身含第 3 类句子 | 规则覆盖的是表面，条数不解决问题 |

## 四、三句演示

只做一件事：去掉“关于这段文字”的那一层，把句子改回对具体人、具体事说。词表不参与。

| 原句 | 改后 | 变化 |
|---|---|---|
| 话讲得满，落不到具体的事上。 | 这份稿子写到“全面提升服务效能”就停了：提升哪一项、谁来验收，都没写。 | 总评换成缺的那件事，评价词没有位置可待 |
| 事实、判断、语气和作者原本的声音，一律不动。 | 数字、人名，还有你原来那句“先别急着报”，改完都在原位。 | 并列判断变成可核清单，读者知道去哪查 |
| 骨架是压掉空转的主力……会自己退场。补骨架比补材料有效得多。 | 先写清谁看、写错会怎样，“持续提升”这类句子就无处落脚；只改字句，它们还在。 | 拟人和金句换成一个可操作的动作加一条后果 |

反向检验：保留“坏词”但不改立场，读起来并不违和，例如“这话他跟甲方说得太满，当场就被砍了两条”。`满` 在句子里，评价词也在，但它有施事、有后果、有听者。用户的原话是“人不是不会用满，只是不会这么频繁地当总评”，这一句正好落在那条边界上。

## 五、为什么补丁注定失败

案例库按表面形状建索引：词、句式、标点。缺陷由位置和功能决定。一个功能可以用任意词汇实现，所以任何词表都会被绕开，绕开一次就换一套词复发，这轮已经被验证一次。

更直接的证据是规则文件本身：`SKILL.md` 第 14 行的“自我评价会自己退场”“补骨架比补材料有效得多”，`references/situating.md` 第 68 行的半句加粗“**上表只在逐句删改时有效。**”，都是被用户指认过的那两类形状。写规则的手和写 README 的手是同一只，所以缺陷跟着位置走，不跟着文件走。

## 六、可检验预测

- P1：在 slop 语料上删去段首标签句与段末总括句，AI 判读率显著下降，信息量不减（删除实验 + 人工判读，未做）。
- P2：人类高质量样本的段末停在细节或下一步动作的比例，高于 AI 疑似样本（未测）。
- P3：同一内容写成“对人说、有后果”，即使保留“满、一律、而……则”等词，读者判为 AI 的比例不升高（未测）。

三条都未跑。在跑之前，下面这套判据只能算设计，不算结论。

## 七、判据改组（换索引，不是加条款）

一级索引由表面特征换成“这句话对谁做了什么”。具体是三条硬约束：

1. 段落起法只有两种：承接上文的具体对象，或直接进入事。不得以“关于本段/本文”的说明起，包括加粗半句、名词短语、预告结论。
2. 段落停在具体处：数字、名字、引文、下一步动作。不以总括、评价、承诺收束。确实要交代边界，就写成条件和后果，不写成判断句。
3. 情境判断（谁写给谁、写错会怎样）只在内部成立，不写进正文。写进去就变成第 1 条禁止的那类句子。

自检只查两处：段首、段末。问一句“这句在说明这段文字，还是在跟人说事”。词表和案例库降为参照物，不再是判据。

## 八、适用范围与边界

本诊断的证据来自本轮失败句、既有实验的对照组修正、492 份语料的按位置统计，以及规则文件的自身对照。语料级删除实验和读者盲评都没做，所以“根治”的说法只到“把一类问题从词表层搬到位置层”，不承担效果承诺。

规则文件里的同类句尚未按第七节清理；一旦按位置重写，改的是规则的组织方式，不是几个句子。
